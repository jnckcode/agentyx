## REPL Persistence & Unexpected Close Prevention - 2026-08-22

### Root Cause Analysis
- Interactive Inquirer slash menu (`/` or `/menu`) hijacked `process.stdin` and closed its internal readline interface upon completion, emitting `'close'` on `process.stdin` and terminating the outer CLI event loop.
- Unhandled `SIGINT` (Ctrl+C) closed `readline` by default without prompt confirmation.
- Asynchronous `startInteractiveRepl` returned immediately after attaching `line` listeners, leaving process lifetime dependent on active stream listeners.

### Technical Solutions
- `[MODIFIED]` `src/index.ts`: Replaced destructive `rl.close()` on slash commands with non-destructive `rl.pause()` / `rl.resume()` and `process.stdin.resume()`. Prevented premature Promise resolution that previously allowed Inquirer's cleanup to terminate Node.js event loop.
- `[MODIFIED]` `src/commands/slash-handler.ts`: Added `finally { process.stdin.resume(); }` block to `promptInteractiveMenu()` to guarantee stdin stays active after Inquirer menu selection.

## Double Input Prevention & Single Readline Instance Architecture - 2026-08-22

### Root Cause Analysis
- The outer `while (isReplRunning)` loop created a *new* `readline.createInterface` instance every time stream events resolved.
- When multiple `readline.createInterface` instances attached to `process.stdin` simultaneously, every input line entered by the user was captured and processed twice (double input).

### Technical Solutions
- `[MODIFIED]` `src/index.ts`: Refactored `startInteractiveRepl` to instantiate a **single persistent `readline.createInterface`** instance. Removed the outer `while` loop to guarantee exactly 1 active listener on `process.stdin`.
- `[MODIFIED]` `src/index.ts`: Handled interactive slash commands via `rl.pause()` during execution, followed by `process.stdin.resume()`, `rl.resume()`, and `rl.prompt()` upon completion.
